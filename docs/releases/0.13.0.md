TUInk 0.13.0 moves the project to Java 25 and Oracle GraalVM, improves file fidelity and syntax context, and adds reproducible optional PGO training.

Changes since [v0.12.3](0.12.3.md).

## Fixes and improvements

- The JVM distribution now requires Java 25 or newer. JVM development uses a Java 25 toolchain from any vendor; native builds use the pinned Oracle GraalVM SDK.
- Mouse selection and scrollbar hit testing use consistent widget geometry. Incremental terminal layouts reuse unchanged line information.
- Bulk line changes avoid repeated insertion and removal work, and incremental consumers can identify the earliest changed line.
- Saving existing files preserves Unix permissions, ownership, user attributes and supported ACLs. A failure reading or applying required attributes aborts replacement and keeps the original file intact.
- Saving to a new name refuses to overwrite a file created concurrently. Non-regular document targets are rejected, and recovery viewports are clamped after a document shrinks.
- Syntax scanning limits lexical work while retaining supported multiline literal and comment context. Quoted comment markers, Rust raw strings and Markdown fence contexts are handled more accurately; highlighting remains approximate for complex constructs.
- Optional PGO training runs checked editing and pointer workloads, verifies saved results and records profile inputs. Target-specific profiles are rejected when their receipts do not match the selected build inputs.
- Native distributions include the Oracle runtime license and third-party notices. Archive installation and removal track the notice files they own and preserve unrelated files.

## Downloads

- `tuink-0.13.0.zip`: JVM distribution; requires Java 25 or newer.
- `tuink-0.13.0-linux-x86_64.tar.gz`: Linux x86_64 native distribution for glibc systems.
- `tuink-0.13.0-linux-x86_64-musl.tar.gz`: Linux x86_64 static musl distribution.
- `tuink_0.13.0_amd64.deb`: Debian package for Linux x86_64.
- `SHA256SUMS`: distribution checksums.

On Linux, saving existing documents requires the `acl` package (`getfacl` and `setfacl`). The musl distribution also requires `tty` and `stty` in `PATH`.

## For builders

For JVM builds, use the Gradle wrapper with a compatible JDK, such as 17, 21 or 25; the Java 25 toolchain is found or downloaded automatically. Native builds require the pinned Oracle GraalVM 25.0.4+7.1 SDK with Java 25, with both `JAVA_HOME` and `GRAALVM_HOME` pointing to that SDK. Use the checked-in Gradle 9.8.1 wrapper. Native releases use Oracle O3 and the portable `compatibility` CPU baseline.

PGO remains optional and experimental; its optimized binaries and profiles are separate from ordinary release outputs. Run `:app:perfHarnessTest` and `:app:pgoHarnessTest` explicitly to verify their Python harnesses; ordinary JVM `check` does not run them. Training requires Python 3.10+ and a POSIX pseudo-terminal.

Settings remain at format 1 and recovery snapshots at format 5. Java toolkit and editor APIs remain internal and incubating.
