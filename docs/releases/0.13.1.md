TUInk 0.13.1 hardens terminal cleanup, search and rendering, and release packaging.

Changes since [v0.13.0](0.13.0.md).

## Fixes and improvements

- Terminal input polling uses bounded positive timeouts. Backspace follows the terminal's advertised erase convention, and leaving the alternate screen preserves the shell's restored contents.
- Rendering verifies row contents after matching cached signatures, preventing hash collisions from leaving stale text on screen.
- Wildcard matching avoids regex backtracking while retaining Unicode match ranges. Backward search includes the starting occurrence when wrapping, and all-tabs navigation shares the same matching behavior.
- Search and rendering share bounded lexical context and Unicode layout information. Wrapped navigation and selection retain consistent logical document positions.
- Debian packaging checks the staged native binary's required library versions before assembly. The package now declares its ACL tools and corrected minimum zlib dependency.
- Release automation verifies the tag, project version, notes, complete asset set and checksums before publication. Benchmark and architecture guidance clarify how to verify the build.

## Downloads

- `tuink-0.13.1.zip`: JVM distribution; requires Java 25 or newer.
- `tuink-0.13.1-linux-x86_64.tar.gz`: Linux x86_64 native distribution for glibc systems.
- `tuink-0.13.1-linux-x86_64-musl.tar.gz`: Linux x86_64 static musl distribution.
- `tuink_0.13.1_amd64.deb`: Debian package; requires glibc 2.34+ and zlib 1.2.2+.
- `SHA256SUMS`: distribution checksums.

On Linux, saving existing documents requires the `acl` package (`getfacl` and `setfacl`). The musl distribution also requires `tty` and `stty` in `PATH`.

## For builders

For JVM builds, use the Gradle wrapper with a compatible JDK, such as 17, 21 or 25; the Java 25 toolchain is found or downloaded automatically. Native builds require the pinned Oracle GraalVM 25.0.4+7.1 SDK with Java 25, with both `JAVA_HOME` and `GRAALVM_HOME` pointing to that SDK. Native releases use Oracle O3 and the portable `compatibility` CPU baseline; optional PGO outputs remain separate.

Debian verification additionally uses Python 3.10+, `readelf` and `dpkg --compare-versions`. Settings remain at format 1 and recovery snapshots at format 5. Java toolkit and editor APIs remain internal and incubating.
