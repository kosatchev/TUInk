TUInk 0.14.0 improves file browsing, viewport behavior, modal focus and help navigation.

Changes since [v0.13.1](0.13.1.md).

## Fixes and improvements

- The file picker loads directory snapshots without blocking terminal input.
- Viewport anchors remain stable while the terminal layout changes, and scrollbars use shared geometry for drawing and pointer input.
- Modal dialogs keep focus and field commands with the active control. Moving within a text field does not accidentally navigate the document behind it.
- Long help pages can be scrolled instead of being cut off by the terminal height.
- Invalid command-line arguments produce diagnostics on standard error and exit with status `2`; help exits with status `0`.
- Failed autosave attempts are debounced. A failed write keeps the previously committed recovery snapshot, while the final snapshot attempt bypasses the retry delay.

## Downloads

- `tuink-0.14.0.zip`: JVM distribution; requires Java 25 or newer.
- `tuink-0.14.0-linux-x86_64.tar.gz`: Linux x86_64 native distribution for glibc systems.
- `tuink-0.14.0-linux-x86_64-musl.tar.gz`: Linux x86_64 static musl distribution.
- `tuink_0.14.0_amd64.deb`: Debian package; requires glibc 2.34+ and zlib 1.2.2+.
- `SHA256SUMS`: distribution checksums.

On Linux, saving existing documents requires the `acl` package (`getfacl` and `setfacl`). The musl distribution also requires `tty` and `stty` in `PATH`.

## For builders

For JVM builds, use the Gradle wrapper with a compatible JDK, such as 17, 21 or 25; the Java 25 toolchain is found or downloaded automatically. Native builds require the pinned Oracle GraalVM 25.0.4+7.1 SDK with Java 25, with both `JAVA_HOME` and `GRAALVM_HOME` pointing to that SDK. Native releases use Oracle O3 and the portable `compatibility` CPU baseline; optional PGO outputs remain separate.

The separate Linux `:app:uiRegressionTest` gate exercises the installed JVM editor through a PTY. It requires Python 3.10+ and a POSIX pseudo-terminal; ordinary JVM `check` remains independent of those requirements. Native benchmark and training receipts record their build inputs.

Settings remain at format 1 and recovery snapshots at format 5. Java toolkit and editor APIs remain internal and incubating.
