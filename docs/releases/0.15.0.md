TUInk 0.15.0 improves editing, Unicode input, small-terminal dialogs and exact filename handling.

Changes since [v0.14.0](0.14.0.md).

## Fixes and improvements

- Help and file dialogs remain usable in small terminals. Window events, pointer capture and focused commands follow the active dialog or editor view.
- Indentation and Markdown list continuation use the surrounding language context.
- Literal paste is one undo step and retains mixed line endings. If an edit leaves an empty line between bare CR and LF endings, its ending becomes CRLF so saving and reopening retain both line breaks.
- Unicode geometry remains consistent across input and rendering. Terminal keys retain incomplete escape-sequence prefixes across reads and idle polls; complete unambiguous keys and Alt combinations are delivered immediately. A bare Esc or an ambiguous complete terminfo key has a window of at most 500 ms.
- Save checks reject unsafe target changes and character-encoding failures while retaining the edited document.
- The `--read`, `--no-mouse` and `--theme` options apply only to the current session. Explicit preference changes through menus or key bindings are saved.
- Confirmation choices are accepted only when the question is visible. A terminal that is too small displays a resize hint while keeping safe cancellation available.
- Pasting into Find, Replace or Save As preserves tabs.
- `--file-uri` accepts ASCII percent-encoded absolute file URIs, including exact native Unix filename bytes and literal replacement-character names. Ambiguous `U+FFFD` command-line paths are rejected before opening a document or profile log.

## Downloads

- `tuink-0.15.0.zip`: JVM distribution; requires Java 25 or newer.
- `tuink-0.15.0-linux-x86_64.tar.gz`: Linux x86_64 native distribution for glibc systems.
- `tuink-0.15.0-linux-x86_64-musl.tar.gz`: Linux x86_64 static musl distribution.
- `tuink_0.15.0_amd64.deb`: Debian package; requires glibc 2.34+ and zlib 1.2.2+.
- `SHA256SUMS`: distribution checksums.

On Linux, saving existing documents requires the `acl` package (`getfacl` and `setfacl`). The musl distribution also requires `tty` and `stty` in `PATH`.

## For builders

For JVM builds, use the Gradle wrapper with a compatible JDK, such as 17, 21 or 25; the Java 25 toolchain is found or downloaded automatically. Native builds require the pinned Oracle GraalVM 25.0.4+7.1 SDK with Java 25, with both `JAVA_HOME` and `GRAALVM_HOME` pointing to that SDK. Native releases use Oracle O3 and the portable `compatibility` CPU baseline; optional PGO outputs remain separate.

Settings remain at format 1 and recovery snapshots at format 5. Recovery paths use display strings; exact native filename bytes accepted by `--file-uri` are not preserved by that snapshot format. Java toolkit and editor APIs remain internal and incubating.

Internally, document text and undo history are shared state, separate from each view's cursor, selection and viewport positions.
