TUInk 0.16.0 adds bounded editing workflows, explicit encoding choices and asynchronous recovery, and strengthens file identity checks.

Changes since [v0.15.0](0.15.0.md).

## Fixes and improvements

- Document loads, edits and clipboard operations check admission limits before publishing changes. Rejected operations retain the existing document and history; accepting a file does not guarantee that every later operation will fit the available heap.
- Wildcard search and replacement use work limits with visible failure feedback. A costly inactive tab no longer suppresses the current tab's count or highlights when All tabs is disabled.
- Syntax highlighting limits lexical work and renders results progressively. Approximate highlighting remains subject to the documented language and work limits.
- Selection can extend across lines and to the start or end of a document. Boundary navigation commands and timed edge scrolling preserve visible context while selecting.
- After an edit joins combining characters or emoji into a new grapheme, subsequent typing continues after the complete grapheme. Undo retains the original selection, including exact search ranges.
- Ambiguous UTF-16LE input can be opened through an explicit choice or `--open-as-utf16le`. UTF-8 conversion is explicit rather than silently changing a document's save encoding.
- Saves check physical file identity. Save As classifies aliases against the document's loaded identity, so selecting a retargeted symlink's new destination requires overwrite confirmation.
- Generated copy and numbered filenames reserve space for their suffix within a 255-byte name budget. Collision checks use the final shortened name and preserve Unicode scalars and native Unix filename bytes.
- Find, Replace and Save As prepare field edits and layout before publication. Refused input preserves field state; deleting a separator leaves the caret after a newly joined grapheme.
- Linux POSIX access ACLs are preserved through libc extended-attribute functions. Saving no longer requires `getfacl`, `setfacl` or a separate `libacl` library; failed ACL checks leave the original file intact.
- Autosave runs outside the UI thread with bounded snapshot resources. Current recovery snapshots preserve native filename information.
- Automatic session preference saves check the settings loaded at startup. If another process changes that file, TUInk preserves it and reports that the session's preference changes were not saved.
- Recovery reads the exact formats 5 through 8, including format-5 drafts from v0.13 through v0.15, while ordinary autosave writes format 8. Discovery and Restore leave older metadata and text unchanged. Ambiguous format-5 paths containing `U+FFFD` restore as dirty unnamed drafts: use Save As to choose a name. Other malformed or foreign-platform paths retain their documented safe handling. Restore old drafts before running old and new binaries together in one profile.

## Downloads

- `tuink-0.16.0.zip`: JVM distribution; requires Java 25 or newer.
- `tuink-0.16.0-linux-x86_64.tar.gz`: Linux x86_64 native distribution for glibc systems.
- `tuink-0.16.0-linux-x86_64-musl.tar.gz`: Linux x86_64 static musl distribution.
- `tuink-0.16.0-linux-x86_64-pgo.tar.gz`: Linux x86_64 PGO native distribution for glibc systems.
- `tuink-0.16.0-linux-x86_64-musl-pgo.tar.gz`: Linux x86_64 PGO static musl distribution.
- `tuink_0.16.0_amd64.deb`: Debian package; requires glibc 2.34+ and zlib 1.2.2+.
- `SHA256SUMS`: distribution checksums.

The musl distribution requires `tty` and `stty` in `PATH`.

## For builders

For JVM builds, use the Gradle wrapper with a compatible JDK, such as 17, 21 or 25; the Java 25 toolchain is found or downloaded automatically. Native builds require the pinned Oracle GraalVM 25.0.4+7.1 SDK with Java 25, with both `JAVA_HOME` and `GRAALVM_HOME` pointing to that SDK. Native releases use Oracle O3 and the portable `compatibility` CPU baseline; optional PGO outputs remain separate.

JVM ACL access uses Java 25's Foreign Function and Memory API; native builds link the libc bridge and verify it through the native ACL smoke gate. PTY regressions cover editing limits, file identity and recovery workflows.

Settings remain at format 1. Java toolkit and editor APIs remain internal and incubating.
