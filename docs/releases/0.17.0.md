TUInk 0.17.0 adds document encoding and line-ending controls, cancellable background saves, and portable editor modules separated from terminal and filesystem adapters.

Changes since [v0.16.0](0.16.0.md).

## Editing and document formats

- File > Format and the ENC/EOL footer controls choose encoding and line endings independently. Supported output formats are UTF-8 with or without BOM, UTF-16LE/BE with BOM, Windows-1251, CP866 and KOI8-R. Apply creates one undoable in-memory change; Save writes it. Unsupported characters reject conversion without substitution. Keep preserves mixed endings; LF, CRLF and CR normalize them while preserving the final-newline state.
- Open with encoding, Reopen with encoding and `--open-as` select the input decoder explicitly. UTF-8 accepts an optional BOM; UTF-16LE/BE require the matching BOM. CP866 and KOI8-R require explicit selection. Reopen confirms discarding edits and clears Undo after success; failed reads or validation retain the document.
- Keyboard edits, typing assists, clipboard cuts, bulk changes and Undo/Redo prepare text, history, mandatory session results and shared-view positions before publication. Failed preparation preserves the draft. Undoing another view's edit retains exact search selections.
- Immutable text blocks and line-ending metadata share unchanged content. Local edits update Unicode and terminal indices from the edited range, with range-based visible text and virtual wrapped rows for fixed-width runs. General word/tab reflow remains linear. Editing and terminal grapheme checks agree for offsets outside the document.
- Search rejects queries exceeding its compilation memory budget while keeping the query editable. Sequential search resumes from accepted matches using bounded caches and sparse checkpoints, retaining non-overlapping matching rules.
- Nearby keyword and closing-delimiter dedent remains available after a long unrelated prefix. YAML block scalars handle compact sequence and mapping indicators. Lexical context and owner searches retain their work limits.
- Search and dialogs remain with their tabs; tab titles show dialog and search badges. Small viewports use consistent control availability and keep modal input contained.
- Rendering, resizing and stop requests remain responsive while draining large terminal pastes, including rejected oversized input.

## Files, recovery and terminal behavior

- Document reads and writes run in a background worker. A pending save locks edits to its document while navigation and other tabs remain usable. Save As approval binds the inspected address and contents and rejects target changes before staging or publication.
- Verification and save preparation show progress and allow cancellation, including large overwrite targets. Access hints are sampled in the background. Once publication begins, quit/shutdown waits up to five seconds for its outcome; an unconfirmed result retains the dirty draft and attempts recovery. Pending opens can be abandoned, and a completed final save exits without another terminal read.
- Saving encodes directly into the staged file through bounded buffers while hashing the written bytes, preserving the selected encoding, BOM and line endings.
- Recovery captures immutable text for background assembly, prepares ownership before publishing restored tabs, and retains snapshot text after uncertain metadata publication or failed cleanup. Final recovery is attempted even when a document operation fails to drain.
- File-picker limits cover the complete expanded tree, including metadata counts. Limits and worker failures clear the loading state. Open, save and directory loading classify typed filesystem failures consistently without interpreting words in filenames as errors.
- Linux startup uses JLine's exec provider to preserve baud rates and terminal attributes on exit. Both `dumb` and `dumb-color` fallbacks are rejected. Interactive Linux runs of every distribution require `tty` and `stty` in `PATH`.
- CLI errors, startup/recovery warnings, exception traces, JLine logs and notifications escape external terminal text while preserving actual file paths.
- `--version` prints the generated application version and exits without opening the terminal or reading settings and recovery data.
- JLine terminal, JNI and native support modules move to 3.30.17, including its security fixes. Shared cell-width tables follow its fixed Unicode ranges and retain visible placeholders for isolated zero-width clusters.
- Distribution documentation and notices match each runtime: JVM archives omit native-runtime bundles, and musl/zlib notices accompany static musl builds. Bundled Markdown links are checked and source-only links identify the packaged revision. Archive upgrades remove retired empty license directories and reject unexpected managed-file types before changing installation contents.

Owned saves retain the pinned physical target and loaded-byte baseline. Per-user locks coordinate TUInk writers across profiles and Unix bind-mounted aliases of one directory entry. These checks cannot prevent a writer ignoring TUInk's locks from changing the destination after final verification. See the [compatibility policy](../compatibility.md) for publication fallbacks, staged-file leftovers and recovery limits.

## For builders

The packaged application still requires Java 25. `editor-contract`, `unicode-text`, `core`, `editor-session` and `highlight-regex` use Java 17 APIs and bytecode. Session and rendering consumers share one document identity. Semantic highlighting is independent of terminal rendering; JGit diff and Linux FFM access live in optional platform modules. External JVM and D8/R8 probes check these boundaries without promising Android storage, lifecycle or ART support. Java toolkit and editor APIs remain internal and incubating.

Native builds retain the pinned Oracle GraalVM 25.0.4+7.1 SDK, Oracle O3 and the portable `compatibility` CPU baseline. PGO training follows the current Replace all controls; PTY checks wait for complete fields, saved bytes and final I/O acknowledgements. Recovery regression hashing retains Python 3.10 support.

Source exports without Git metadata must supply `-PdocumentationRef=<full-commit-or-version-tag>` to packaging and documentation checks. Settings remain at format 1. Recovery readers accept exact formats 5 through 8, and writers use format 8.
