TUInk 0.19.0 adds a persistent folder explorer, guarded file operations and
file Undo/Redo, and explicit handling of missing or externally changed files
in Source and Markdown Preview.

Changes since [v0.18.0](0.18.0.md).

## Folder explorer and file history

- Open a directory with `tuink .`, `tuink path/to/folder`, or **Explorer → Open
  folder...**. The left tree keeps its root, expansion, selection and scroll
  position across tab changes. Closing or changing the root preserves open
  documents and unsaved edits. Ctrl+B toggles the panel, Ctrl+E focuses it,
  and Esc returns to the document. Drag the divider to resize; narrow terminals
  temporarily hide the panel and restore its preferred width when space returns.
- F7 opens the Explorer menu with file/folder creation, Rename, Copy, Move,
  Move to Trash, permanent Delete, Refresh and width presets. Destination
  pickers remain read-only. The root supports creation and copying outside
  its tree, while rename, move and removal apply only to its children.
- Folder selection updates the chooser's Path field and confirmation uses that
  directory. Copy/Move use the sidebar's relative tree by default; **Use full
  path** enables unrestricted browsing without changing the selected destination.
  Scrolling the destination tree preserves an unfinished Path edit.
- **View → Document Path** shows the current path in Source and Preview and is
  enabled by default. Explorer-opened documents use relative paths; other opens
  use full paths. Middle directories collapse before the filename is shortened.
- Hold an entry for one second and drag onto a folder to move it. Hover expands
  folders, edge dragging scrolls, and Escape cancels. The filesystem changes
  only after release over a valid destination.
- Explorer Undo/Redo reverses creation, copying, renaming and moving. Ctrl+Z/Y
  uses file history only while the sidebar has focus. Identity and destination
  checks protect changed or replaced entries; Undo Create requires the same
  empty object. Mixed nested operations retain their identities across repeated
  Undo/Redo and transfers between filesystems. Accepted atomic saves update
  move/rename identities without allowing Undo to remove saved content.
- Copy reads on-disk contents, preserves symbolic links and their timestamps,
  and leaves open document bindings and unsaved text intact. Undo checks the
  complete copy; Redo checks its source. Copies above the 10,000-entry history
  budget complete with a warning and no Undo.
- Move to Trash uses the Linux system Trash when available and never falls
  back to permanent deletion. Trash and permanent Delete cannot be undone in
  TUInk and clear earlier file history. System tools can restore trashed files.
- Successful file Undo/Redo shows a temporary yellow sidebar notice. The new
  **File Undo/Redo notifications** setting controls these success notices;
  errors remain visible.

## Missing files and external changes

- Rename and Move preserve open Source/Preview identities, dirty text and text
  history while updating their resource bindings. Removing an open file keeps
  its text as an unnamed dirty draft requiring Save As. A persistent yellow
  banner retains its former name until a successful file save or Dismiss.
- Active files are checked in the background: metadata roughly every second
  and bounded content reads roughly every five seconds even when metadata is
  unchanged. Activation and Refresh request fresh checks. These are periodic
  reads without an OS filesystem watcher.
- Changed disk bytes show **Keep / Update** below Source or Preview. Keep
  retains local text and format while acknowledging that exact disk baseline.
  Update accepts text and format in one Undo step, preserving earlier local
  history and historical gutter markers. Undo retains the acknowledged disk
  baseline. **File → Update from disk** remains available after Keep.
- Source and Live Preview share the decision. Frozen Preview has its own
  session Undo/Redo and can save retained text to its bound file. Unsaved frozen
  text participates in Save/Discard/Cancel on close or quit and in recovery.
  Reopening Source preserves a frozen draft or its history in its own tab.
- Own saves do not cause false external warnings. Newer disk versions, stale
  results, decoding errors and read failures preserve the buffer. External
  changes never reload text automatically.

## Controls and terminal appearance

- Preview uses the shared Find toolbar with Case, word, wildcard and Next/Prev
  controls. Replacement commands remain unavailable in Preview.
- Search, Save As, confirmations, notifications and status stay inside their
  document pane; the neighbouring tree keeps its height. Quit confirmation
  spans the full window. File dialogs share the Help/Open popup styles.
- Terminal-reported default and ANSI foregrounds are resolved explicitly on
  deep-color terminals so bold retains the ordinary text color. OSC replies
  are bounded and do not consume unrelated control input. The explorer divider
  uses the active theme accent.
- Deferred opens and encoding choices retain their original sidebar/picker
  context and preserve newer focus, dialogs and tab selection. Very short or
  narrow terminals keep document, tab, field and caret geometry consistent.

## Compatibility and builders

- Settings remain at format 2. Optional `ui.fileHistoryNotifications` defaults
  to `true`; existing profiles remain readable without conversion. Recovery
  remains at format 8 and retains current text, format and accepted disk
  baseline. Session Undo/Redo and the original-open text for historical gutter
  markers are not persisted across restart.
- `tuiframe-explorer` owns the reusable filesystem model, UI, gestures, file
  operations and bounded history. TUInk adapts operation receipts to document
  bindings. Shared editor and Markdown contracts retain their Java 17 baseline;
  the application and packaged JVM distribution require Java 25.
- JVM, glibc, static musl and both optimized PGO distributions share the
  documented release contract. Native builds still require the pinned
  Oracle GraalVM 25.0.4+7.1 SDK. See the [build guide](../building.md) and
  [packaging guide](../packaging.md).
- The explorer has one root and keeps its state for the current run. Root
  restoration across launches and an OS filesystem watcher are not included.
