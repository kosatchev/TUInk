# Взаимоисключающий ввод окна

Контракт выбора единственного получателя ввода для Source, Preview и полей окна.

`WindowInput` — конечное решение о действии, адресованное `UiRecipient`.
Он находится в `terminal-ui`, поскольку описывает ввод конкретного frontend,
а не переносимую команду документного движка.

| Вариант | Данные | Единственное допустимое действие |
|---|---|---|
| `Consumed` | Нет исполняемых данных | Завершить обработку |
| `Command` | Исходный `CommandInvocation`, проверенный `RoutedCommand`, получатель | Выполнить семантическую команду |
| `Text` | Значение, признак paste и усечения, получатель | Передать текст соответствующему получателю |
| `Gesture` | Указатель с модификаторами либо смещение viewport, получатель | Передать жест соответствующему получателю |

Команда не хранит исходный клик, текст или клавишу. Преобразование выбранного
пункта меню сохраняет уже проверенный route без повторного dispatch.
Параметризованный `ActivateTab` сохраняется вместе с аргументами invocation.
Неизвестная или некорректная команда превращается в `Consumed`: её физическое
происхождение не служит резервным способом ввода в документ.

Обычный текст сохраняет Unicode scalars. Paste остаётся отдельным намерением
внутри текстового варианта: сохраняются переводы строк и признак усечения.
Поле ввода адаптирует только полученный вариант в событие общего `TextField`;
исполняемого физического события рядом с командой не существует.
Alt+стрелки представляются смещением viewport, без передачи произвольной
непривязанной клавиши обработчику содержимого.

События resize/lifecycle обрабатываются до этой границы. Меню, диалоги,
pointer capture, команды и редактирование полей используют общие маршруты
с явными владельцами. Обработчик содержимого получает только разрешённое
намерение без пары физического события и команды.

Проверки контракта находятся в `WindowInputTest`,
`TerminalEditorInputRoutingTest` и `HelpHintsControllerTest`. Сквозные проверки
`PreviewMenuPointerIntegrationTest`, `EditorCommandRoutingIntegrationTest`,
`MarkdownPreviewSearchFieldIntegrationTest` и `DialogBehaviorIntegrationTest`
проверяют взаимодействие с существующими получателями.

`executeResolvedCommand` проверяет актуального получателя и capabilities для
всех семантических команд, включая параметризованные команды вкладок.
`CommandRegistry.accepts` выполняет side-effect-free preflight исходного
binding перед raw-переходом виджета. `invoke` проверяет актуальную регистрацию
и schema перед единственным вызовом handler. Исходные аргументы не стираются
контекстным search remap; owner intents выполняются после approval.

## Системный буфер обмена

Переносимый `ClipboardPort` описывает чтение и запись обычного текста.
Конкретный frontend выбирает адаптер и правила его выполнения: терминальный
`ProcessClipboard` вызывает desktop helpers вне потока ввода и рисования.
Engine, session, Markdown layout и виджеты не обращаются к ОС.

`EditorClipboard` остаётся общим внутренним буфером workspace. Его `revision`
меняется при публикации, включая повторное копирование того же текста.
Откат неподтверждённой команды восстанавливает текст и revision вместе;
пустые Copy/Cut не публикуются. Один `SystemClipboardController` наблюдает
успешные публикации редактора, Preview, source/TSV и всех полей после dispatch.
Он последовательно выполняет ограниченные по времени системные операции,
объединяет ожидающие записи и завершает их перед следующим чтением.

Ctrl+V читает системный текст, проверяет исходные presentation, modal, поле,
выделение и revision документа, затем повторно использует ту же команду Paste.
Импорт текста обновляет внутренний буфер без обратной записи в ОС. Пустая
строка отличается от недоступного clipboard: первая вставляет пустой текст,
второй сохраняет внутренний fallback. Terminal `PasteEvent` уже содержит текст
и не читает системный буфер повторно.

Пока чтение не завершено, ограниченная FIFO сохраняет порядок последующего
ввода. Очередь работает до raw routing, поскольку маршрутизаторы полей могут
редактировать их ещё до dispatch семантических команд. Между отложенными
событиями frontend подготавливает актуального владельца и новый кадр с
placements. Frame fence сохраняется также при переполнении FIFO. Закрытие
отзывает callbacks и права позднего receipt на вставку; worker хранит только
текст, платформенный порт и непрозрачный token операции.

Регрессии: `EditorClipboardTest`, `EditorEngineDocumentCommandTest`,
`SystemClipboardControllerTest`, `ProcessClipboardTest` и
`SystemClipboardIntegrationTest`. Сквозной сценарий
`verification/ui/clipboard.py` использует настоящий PTY и собственный helper,
не затрагивая системный буфер пользователя.

Опциональный `Right-click: copy/paste` разрешает получателя по текущим
`RoutedTarget`, clipped placements и общей геометрии текстовых viewport.
Сначала учитываются capture, mouse capability, modal policy и реальные
текстовые поля. Фокус меняется на найденного владельца без синтетического
левого клика, поэтому caret и выделение не перемещаются к указателю.
Затем выполняется обычный `EDIT_COPY` или `EDIT_PASTE`. Выделение снимается
только после подтверждённой clipboard publication; Source использует session
`Select(RESTORE, caret, null)`, поля и Preview — операции collapse, сохраняющие
caret, viewport и визуальную позицию. Отказ подготовки Copy или collapse
оставляет окно рабочим; история документа при Copy не меняется.

`MD copy as displayed` меняет только формат обычного Copy содержимого Preview.
И Ctrl+C, и ПКМ проходят через один обработчик, выбирающий semantic projection
или готовую раскладку с copy metadata. Схемы и формулы копируются символами;
структурные переводы строк и пробелы сохраняют геометрию. Soft wrap обычного
текста собирается обратно в логические строки. Экранный cell buffer, viewport,
скрытый редактор и повторный вызов math/Mermaid providers для этого не нужны.
Явные source/TSV actions и clipboard полей сохраняют собственные форматы.
Дополнительная удерживаемая metadata учитывается в том же layout budget;
буфер публикуется только после подготовки полного текста копирования.

Доступность команд описывает `ActiveSurface.availability`: разрешение и причина
отказа вместе. Меню и обработчик команды используют этот же результат.
Generic `MenuBar.Unavailable` сообщает о попытке активировать полностью видимый
неактивный пункт, сохраняя открытое меню и выбранную строку. Адаптер передаёт
попытку отдельно от обычного invocation; действие не выполняется. Причина
отображается существующим notification bar, как при вызове команды клавишами.
Обрезанные, скрытые пункты и разделители сохраняют прежние правила ввода.
